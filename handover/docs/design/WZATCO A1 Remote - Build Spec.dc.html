1 · Mission

Build a Kotlin Android application named WZATCO A1 Remote that turns the phone into a Bluetooth HID device and drives a WZATCO Alpha A1 projector with no software installed on the projector. Twelve functions must reach one screen: D-pad with OK, Back, Home, Menu, Volume up/down, Mute, Power, Focus +/−, Source, Screen flip, Keystone, plus a cursor mode. Eight of those map to standard HID usages and can be finished without the projector. Five are projector-specific and unknown; the app ships a discovery tool ("Key Lab") that resolves them against the real hardware and writes the result back into its own key map.

Definition of done

The app installs on the phone, registers as a Bluetooth HID device, pairs with the A1 from the projector's own Bluetooth settings, and drives navigation, OK, Back, Home, Menu, volume and mute reliably from a cold start. Key Lab produces a JSON findings file for every unresolved function. Unit and instrumented test suites pass, ./gradlew build is clean, and the manual test matrix in §10 is filled in.

2 · Stack and constraints

  • Kotlin, Jetpack Compose, single-module :app to start; extract :hid only if it earns its own tests.
  • minSdk 28 — BluetoothHidDevice arrived in Android 9 (API 28) and is the whole basis of the design. targetSdk 35.
  • No third-party Bluetooth libraries. Platform APIs only, so nothing hides a failure mode.
  • Persistence: DataStore (Proto or Preferences) for the key map and Key Lab findings. No database.
  • No projector-side APK and no HomeMate IR dependency in v1. Both stay as documented fallbacks (§11).
  • Offline. No network permission at all — the app must build and run with the internet permission absent.

4 · HID report descriptor

One descriptor with three top-level collections and distinct report IDs, so a keyboard press, a consumer-control press and a cursor move never collide:

  • Report 1 — Keyboard (Generic Desktop / Keyboard): 1 modifier byte + 1 reserved + 6 key slots. Carries arrows, Enter, Escape, Application, and the F-key candidates.
  • Report 2 — Consumer Control: one 16-bit usage field. Carries volume, mute, power, AC_Back, AC_Home and the zoom candidates.
  • Report 3 — Mouse: 3 buttons + relative X/Y (8-bit signed) + wheel. Cursor mode only.

Register with BluetoothHidDeviceAppSdpSettings: name "WZATCO A1 Remote", description "Projector remote", provider "narmeshnigam", subclass SUBCLASS1_COMBO. Every key press is two reports — a key-down and a matching all-zero key-up — and the up report is guaranteed even if the finger leaves the button or the composable leaves the tree.

Gate 1 — do this before any UI work

Prove on the actual phone that BluetoothHidDevice.registerApp() returns true and a paired host receives an arrow-key report. Some OEM ROMs restrict the HID Device profile; if the phone fails this gate, no amount of app code fixes it and the phone must change. Report the outcome before continuing.

6 · Interaction rules

The remote is used in a dark room, one-handed, without looking at the phone. These are requirements, not preferences.

  • Minimum touch target 58 × 58 dp; 6 dp gutters. No key smaller than any other in its row.
  • Fixed geometry. The keypad never scrolls and rows never reflow — position is the only cue a thumb has.
  • Press feedback: the cell fills with the accent for 90 ms and a 12 ms haptic tick fires on key-down, not key-up.
  • Auto-repeat on Up/Down/Left/Right, Volume and Focus: 400 ms delay, then every 90 ms while held.
  • Power requires a 600 ms long-press and a confirming double haptic — it must not be reachable by accident.
  • Screen stays awake while the remote screen is foreground; the app claims no lock-screen presence in v1.
  • If the host disconnects, keys grey out immediately and the status line says so. Never queue reports for a dead link.

8 · Key Lab protocol

Key Lab exists because the A1's projector-specific keys cannot be guessed from a desk. For each unresolved function it walks a candidate list, one report at a time, and records what the projector did.

  1. Pick the function. Show candidate n of m with its exact usage.
  2. Send transmits one key-down/key-up pair and nothing else, so the projector's reaction is unambiguous.
  3. The operator marks It worked or No effect. A hit promotes that candidate into KeyMap immediately and advances to the next function; a miss advances to the next candidate.
  4. Findings persist across restarts and export as JSON: function, usage, verdict, timestamp, app version.

Ship these candidate lists: Focus + — Zoom In 0x022D, F5 0x3E, AC_Forward 0x0225, Keypad + 0x57. Focus − — Zoom Out 0x022E, F6 0x3F, Keypad − 0x56. Source — Media Select TV 0x0089, F4 0x3D, Channel + 0x009D. Screen flip — F3 0x3B, F1 0x3A, then a swept range. Keystone — F2 0x3B, F7 0x40, then a swept range. Include a manual mode where the operator types any usage code by hand, and a sweep mode that walks a range with a 700 ms gap and a visible index so the operator can call out where the projector reacted.

9 · Permissions and lifecycle

  • BLUETOOTH_CONNECT and BLUETOOTH_ADVERTISE (API 31+), legacy BLUETOOTH/BLUETOOTH_ADMIN for 28–30, FOREGROUND_SERVICE + FOREGROUND_SERVICE_CONNECTED_DEVICE, VIBRATE. No location permission and no INTERNET.
  • Ask for permissions from a rationale screen, never on cold launch. A denial must leave the app usable and honest about what is blocked.
  • Unregister the HID app and release the proxy in onDestroy; re-register idempotently on next start. Never leak a registration across process death.
  • Reconnect: on host disconnect, retry the last known host three times with backoff, then wait for a manual connect.

10 · Tests

  • Unit — descriptor bytes match the spec; every function produces the exact expected report pair; key-up always follows key-down; auto-repeat timing; KeyMap override and reload; Key Lab promotion logic; JSON export round-trip.
  • Instrumented — service registers and unregisters cleanly across rotation and process death; permission flows; every key reachable and 58 dp or larger; no report sent while disconnected.
  • Fake host — a test double for BluetoothHidDevice that captures reports, so the whole app is testable without the projector.
  • Manual matrix on the A1 — for each of the twelve functions record: reaction, latency, repeat behaviour, behaviour after 10 minutes idle, behaviour after projector standby. This is the document that closes the project.

Verification per change: ./gradlew ktlintCheck detekt test connectedAndroidTest assembleDebug. Keep the build warning-free; treat a new warning as a failure.

11 · Fallbacks — not in v1

If a function survives Key Lab unmapped, it is vendor-internal, and only then do these open up: a projector-side companion APK driving the vendor service or Android UI automation, or the existing HomeMate IR blaster for that one function. Do not build either speculatively, and do not make HomeMate a dependency of the app. Record the unmapped function in the findings file and stop.

13 · Open questions

Answer these from the hardware and record the answers in the repository; do not design around a guess. Does the phone's ROM permit HID Device registration? Does the A1 keep its Bluetooth host alive in standby — i.e. can Bluetooth power the projector on, or is that IR-only? Does Consumer Power 0x0030 turn it off, or only sleep the Android layer? Are Focus, Source, Flip and Keystone reachable as input events at all, or handled by a vendor service above the input stack? Until the standby answer is known, the app must never present a power-on affordance it cannot honour.
